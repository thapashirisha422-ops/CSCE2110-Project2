Smart Campus Navigation and Facility Analytics System

DESIGN DOCUMENT - FINAL SUBMISSION

1. PROJECT OVERVIEW

This project is a C++ console application that uses a custom hash table, campus graph, and general tree to manage campus information.

2. FACILITY DATABASE AND HASH TABLE

The system stores facilities in a custom hash table and supports searching by facility ID, complete name, and category.

Hash function: The facility ID is converted to uppercase. Starting with 0, the hash value is calculated using (hashValue * 31 + ASCII value of character) % capacity for each character.

Hash table capacity: The default capacity is 17 buckets. A prime number is used to help distribute facilities across buckets.

Collision strategy: Separate chaining using vectors. Facilities that hash to the same bucket are stored together.

Separate chaining was chosen because each bucket can store multiple facilities, so the table does not become full even when all 17 buckets are occupied.

Collision counting method: A collision is counted when a new valid facility is inserted into a bucket that already contains another facility. Rejected duplicates are not counted.

3. CAMPUS GRAPH

The system represents campus buildings as vertices and walkways as undirected edges.

Graph representation: The system uses an adjacency list to store buildings and their connections. Each walkway is an undirected edge, so both buildings are added to each other's neighbor lists. This makes it easy to display connections and perform BFS.

Breadth-First Search (BFS) uses a queue and a visited structure to find reachable buildings and their distances.

4. DEPARTMENT TREE

The system uses a general tree to represent academic departments.

Each department has a name, a parent, and a list of children. The tree starts with one root department. It supports adding departments, searching by name, displaying the hierarchy, preorder, postorder, and level-order traversals, and department statistics. Duplicate department names are not allowed.

5. CODE ORGANIZATION

src/ - Contains the C++ implementation files.

include/ - Contains the header files.

data/ - Contains the instructor-provided input files.

testdata/ - Contains additional files for testing.

main.cpp handles the menu and loads the data files.

FacilityHashTable and FacilityLoader manage facility storage and loading.

CampusGraph manages building connections and BFS.

DepartmentTree and DepartmentLoader manage the department hierarchy.

6. INPUT VALIDATION AND ERROR HANDLING

The program validates user input and file records to prevent invalid data from being processed.

The menu checks for blank, nonnumeric, and unavailable options. Facility IDs are validated before searching, and department operations check for duplicate names and missing parents.

The data loaders report accepted and rejected records. Invalid records are rejected with warning messages, while valid records continue loading.

The Department Tree also handles special cases such as an empty tree, a root-only tree, and searches for departments that do not exist.

These checks allow the program to continue running after invalid input instead of terminating unexpectedly.

7. TESTING AND VERIFICATION

The system was tested using valid input files, invalid records, and additional test datasets.

Department Tree testing included adding departments, searching for existing and nonexistent departments, checking duplicate names, rejecting invalid parents, and verifying tree traversals.

Additional tests checked department statistics for a normal tree, an empty tree, and a root-only tree.

For the original dataset, the Department Tree contained 7 departments, 4 leaf departments, and a height of 2.

After adding Robotics under College of Engineering, the tree contained 8 departments, 5 leaf departments, and a height of 2.

The complete testing results are documented in test_results.txt.


8. FINAL PROJECT FEATURES

Facility Searches and Report:
Facility name and category searches use a loop to check the accepted records. The searches ignore capitalization and extra spaces at the beginning and end of the input. The category report counts facilities in each category and calculates their percentages.

Shortest Path:
The campus graph uses BFS with a queue and a parent vector to find the shortest path between two buildings. The parent vector helps reconstruct the path. The program displays each building in the path and the total number of connections. It also handles unknown buildings and disconnected routes.

Graph Connectivity Report:
The report displays the total buildings, connections, buildings with the highest degree, isolated buildings, and connected components. BFS is used to count connected components.

Department Tree:
The final version includes postorder and level-order traversal. Postorder visits children before their parent. Level-order uses a queue to visit departments one level at a time. The statistics report displays the total departments, leaf departments, and tree height.

Memory Management:
The DepartmentTree destructor deletes dynamically allocated tree nodes when the program finishes.
