CSCE 2110 - Project 2  
Smart Campus Navigation and Facility Analytics System

DESIGN DOCUMENT - MILESTONE 1

1. PROJECT OVERVIEW

This project is a C++ console application that uses a custom hash table, campus graph, and general tree to manage campus information.

2. FACILITY DATABASE AND HASH TABLE

The system stores facilities in a custom hash table and supports searching by facility ID.

Hash function: The facility ID is converted to uppercase. Starting with 0, the hash value is calculated using (hashValue * 31 + ASCII value of character) % 17 for each character.

Hash table capacity: 17 buckets. A prime number is used for the table size to help distribute facilities across buckets.

Collision strategy: Separate chaining using vectors. Facilities that hash to the same bucket are stored together.

Separate chaining was chosen because each bucket can store multiple facilities, so the table does not become full even when all 17 buckets are occupied.

Collision counting method: A collision is counted when a new valid facility is inserted into a bucket that already contains another facility. Rejected duplicates are not counted.

3. CAMPUS GRAPH

The system represents campus buildings as vertices and walkways as undirected edges.

Graph representation: The system uses an adjacency list to store buildings and their connections. Each walkway is an undirected edge, so both buildings are added to each other's neighbor lists. This makes it easy to display connections and perform BFS.

Breadth-First Search (BFS) uses a queue and a visited structure to find reachable buildings and their distances.

4. DEPARTMENT TREE

The system uses a general tree to represent academic departments.

Each department has a name, a parent, and a list of children. The tree starts with one root department. It supports adding departments, searching by name, displaying the hierarchy, and preorder traversal. Duplicate department names are not allowed.

5. CODE ORGANIZATION

src/ - Contains the C++ implementation files.

include/ - Contains the header files.

data/ - Contains the instructor-provided input files.

testdata/ - Contains additional files for testing.

main.cpp handles the menu and loads the data files.

FacilityHashTable and FacilityLoader manage facility storage and loading.

CampusGraph manages building connections and BFS.

DepartmentTree and DepartmentLoader manage the department hierarchy.
